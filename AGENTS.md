# PoTATo — Pokémon Champions Teambuilder

## Goal
Build a browser-based Pokémon Champions planning tool with format-accurate data for Regulation M-A (Apr 8 – Jun 17 2026). Lazy-load per-format data: index first (Pokémon list), moves/learnsets/items on demand.

## Stack
- **Language**: Vanilla JavaScript (ES modules)
- **Serve**: `python3 -m http.server`
- **Data**: Pre-merged static JSON files per format, generated by `prep/prep_data.py`
- **No frameworks, no bundlers, no build step**

## Data Pipeline

### Sources
1. **Base data**: `https://play.pokemonshowdown.com/data/pokedex.json` (SV-era stats/moves)
2. **Mod overrides**: `https://raw.githubusercontent.com/smogon/pokemon-showdown/master/data/mods/champions/` — `moves.ts`, `items.ts`, `abilities.ts`, `formats-data.ts`, `learnsets.ts` (Champions-specific balance changes)
3. **Legality lists**: Hardcoded in `prep/prep_data.py` (Regulation M-A species/moves/items from MetaVGC lists)

### Logic
1. Fetch base JSON files from Showdown servers
2. Fetch mod TS files from GitHub, parse them (regex-extract the override objects)
3. Merge: base values → apply mod overrides on top
4. Filter by Regulation M-A whitelists (species, moves, items)
5. Include battle-only forms (megas, regionals, Rotom appliances) — added from pokedex `otherFormes`
6. Output 4 JSON files per format into `data/format-{id}/`
7. Mega learnsets inherit from their `baseSpecies`
8. Floette (base) is included in learnsets since Floette-Mega's `battleOnly` is "Floette-Eternal" but the base Floette is the actual pre-evo

### Critical Discovery
`isNonstandard` **cannot** be used for M-A legality filtering:
- Floette-Mega has `isNonstandard: "Future"` but IS legal in M-A
- Floette-Eternal has `isNonstandard: "Past"` but shows 14.6% usage
- The mod's `formats-data.ts` has a `tier` field as source of truth for Champions legality
- M-A legality = Champions mod non-Illegal species ∩ corrected M-A whitelist ∪ overrides
- Species whitelist is still needed because Champions includes species banned in M-A format (legends, mythicals) — 46 extra forms filtered out

### Species Legality Pipeline (prep_data.py)
1. **Champions legality**: mod `formats-data.ts` entries with `tier != "Illegal"`
2. **M-A whitelist**: 213 non-Mega + 60 Mega IDs (fixed version of MetaVGC-derived list)
3. **Overrides**: `meowsticf` (gender form not in mod formats-data)
4. **Mega detection**: use pokedex `forme` field not string match (fixes Meganium misclassification)
5. **Validation**: warn on whitelist species not in mod data, AND mod species not in whitelist

### Sprite Source
Menu sprites are downloaded from [Bulbagarden Archives](https://archives.bulbagarden.net/wiki/Category:Champions_menu_sprites) using their MediaWiki API. The download script computes the file URL from the MD5 hash of the filename (MediaWiki's standard `{hash[0]}/{hash[0:2]}/{filename}` path convention). Sprites are saved to `sprites/champions/` as PNGs, then `sprite-map.json` maps each species ID to its filename using dex number + form suffix matching.

### Champions Mod Changes Verified
- Trop Kick: 70 → **85 BP**
- Moonblast: added 10% SpA drop chance
- Various other buffs/nerfs in Champions-specific gameplay

### Ability Data Pipeline
1. Fetch abilities from Showdown base data (`pokedex.json`), apply Champions mod overrides
2. Filter to M-A legal species only
3. Fetch descriptions from Game8 page (`https://game8.co/games/Pokemon-Champions/archives/590403`) via regex `<tr>\s*<td[^>]*class="center"[^>]*>\s*(?:<a[^>]*>)?\s*([A-Za-z][A-Za-z\s\'\-]+?)\s*(?:</a>)?\s*</td>\s*<td[^>]*>([^<]+)</td>` — falls back to Showdown `desc` on failure
4. Attach `pokemon` array (species IDs that can have the ability) and `effectCategories` array (broad mechanic tags like `weather`, `stats`, `priority`, etc.)
5. `num` field removed (Showdown internal ID, not used in frontend)
6. Battle Bond excluded (not on Game8 list)
7. Categories defined in `get_ability_categories()` in `prep_data.py` using explicit ID-based assignment

### Item Data Pipeline (prep_items.py)
1. Fetches item sprites and descriptions from Game8's local HTML cache per format
2. Patches sprite paths to `sprites/items/{id}.png` and `shortDesc` field
3. Strips non-display fields (`fling`, `isChoice`, `isBerry`, `itemUser`, etc.)
4. Assigns `category` array via explicit ID-based and keyword rules:
   - **Mega Stone**: items with `.megaStone` field
   - **Berry**: item ID contains `'berry'`
   - **Power Boost**: desc contains `'1.2x power'` OR shortDesc contains `'by 20%'` / `'boosts the power'`
   - **Stat Boost**: White Herb, Choice Scarf, Light Ball (explicit IDs)
   - **Defense**: Focus Band/Sash + type-resist berries (keyword: `'supereffective'` in shortDesc)
   - **Recovery**: status-cure/HP/PP berries + Leftovers, Shell Bell, Mental Herb
   - **Other**: items with no other category
5. Downloads missing item sprites

## Running

```bash
# Fetch/merge data (requires network on first run, caches to .cache/)
npm run prep

# Download Champions menu sprites from Bulbagarden Archives
python3 scripts/download-sprites.py

# Build sprite → species mapping
python3 scripts/build-sprite-map.py

# Start dev server
npm start                # → http://localhost:8787
```

## Frontend Architecture

### Current State
- **`app.js`** (~144 lines): Top-level wiring — DOM queries, `loadFormat`, `initApp()` call, format select listener. No component implementations.
- **`lib/app-state.js`**: Centralized state object with getter/setter functions. Holds `currentFormat`, `teams`, `currentTeamId`, `allSpecies`, `spriteMap`, `shinySpriteMap`, `cachedItems`.
- **`lib/app-init.js`**: Initialization orchestration. Creates all widgets (BreadcrumbView, HeaderView, SearchDetailView, NavigationController, DetailController, PokemonSearchWidget, lazy subtab inits). Calls `loadIndex` preload and `ensureTeamBuilder`.
- **`lib/detail-controller.js`**: Coordinates detail view navigation between `breadcrumbView`, `nav`, and `searchDetailView`.
- **`lib/navigation-controller.js`**: Tab/subtab switching, responsive routing. Defines `TAB_REGISTRY` with side/panel/subtab layout.
- **`lib/views/header-view.js`**: Team bar, team select dropdown, new team button, duplicate species warning, format select.
- **`lib/views/breadcrumb-view.js`**: Breadcrumb trail management with click navigation.
- **`lib/views/search-detail-view.js`**: Pokemon/Move/Ability/Item detail panels with child widgets.

### Widget Lifecycle Pattern
Widgets are created lazily on first tab activation. `app-init.js` holds widget references on the `widgets` object and destroys/recreates them on format change:

```javascript
// Lazy init pattern
if (!movesWidget) {
  movesWidget = new MoveSearchWidget({ container, formatId, ... });
}

// Cleanup on format change
if (movesWidget) { movesWidget.destroy(); movesWidget = null; }
```

### Component Communication
- View components receive callbacks and data getters via constructor options
- `app-init.js` acts as wiring layer — creates components, passes callbacks between them
- Components read state through getter functions passed in, never directly import `app-state.js`
- `app.js` passes the `widgets` object to `initApp()` which populates it

### Three PokemonSearchWidget Instances
1. Main grid (`pokemonWidget`) — Pokédex tab, created eagerly in `app-init.js`
2. Move detail "Learned By" list — within SearchDetailView
3. Ability detail "Pokémon with..." list — within SearchDetailView
- All use `.ps-*` prefixed class selectors to avoid CSS ID conflicts

### Two MoveSearchWidget Instances
1. Moves subtab (`movesWidget`) — full move list, lazy-initialized
2. Pokemon detail moves list (`detailMovesWidget`) — filtered by species learnset, managed inside SearchDetailView

### Click-Highlight Pattern
- Uses direct DOM class toggling (`.selected`), not re-renders
- Avoids full widget refresh on selection change

### Breadcrumb Navigation
- BreadcrumbView manages `items[]` and `activeIndex` internally
- `reset(item)` — starts new trail
- `push(item)` — appends if not duplicate, truncates if navigating back
- `onNavigate` callback fires on breadcrumb click

### Widget Lifecycle
- Widgets created lazily on first tab activation (moves, abilities, items subtabs)
- Pokemon widget created eagerly (default view)
- Team builder, defensive coverage, move coverage widgets created lazily via `ensure*()` functions on first tab visit
- `app.js` holds widget references and calls `destroy()` on format change
- New data passed via `setData()` or re-initialization

### SearchDetailView Sub-Widgets
- Manages its own child widgets: `detailMovesWidget`, `moveDetailPokemonWidget`, `abilityDetailPokemonWidget`
- Destroys children before rendering new content
- Listens to `potato-team-change` event for add-to-team button refresh
